# 未分类核心支出保守计提 Spec

## 1. 目标

修复“正文没有逐项给出住房、医疗、抚养等金额时，成年人的全部持续支出长期退化为 0.35 万/月”的系统性低估。

0.35 万/月继续作为 `adult_basic_living` 的非住房最低线，不再承担“全部核心支出”的含义。支出率只作为路线诊断指标，不是账本写入规则，也不是优化目标。

## 2. 权威边界

- 已接受的分类事实继续写入 `primary_residence`、`elder_care`、`recurring_healthcare` 等类型化账户。
- 分类事实不足时，系统可建立 `unclassified_core_consumption`，其语义固定为 `needs_review + contextual_estimate`。
- 该账户参与现金计提和净资产派生，但不得在正文、报告或海报中冒充具体住房、医疗、保险、赡养或育儿事实。
- 模型 Proposal 不得直接创建或修改该账户；它只能由 Preview 与 Commit 共用的确定性策略产生。
- 同一 AI 叙事重复出现不能把估算升级为已确认事实；升级仍须来自本轮 Accepted 精确事实。

## 3. 估算规则

- 使用就业状态、居住安排、城市成本档位、年龄阶段和已接受的个人持续收入作为上下文。
- 收入只选择有上限、边际递减的统计档位，不使用固定支出率，不按现金或净资产同比例放大。
- 家庭人数只进入审计上下文；付款人、共同份额不明确时，不据此编造个人应付金额。
- 学生与家庭同住或住宿已提供时，不应用收入档位；使用学生基础生活策略，不制造个人债务。
- 没有新事实的后续节点沿用上一个有效账户，不重新退回 0.35 万/月。
- 本轮起始边界已经 Accepted 的就业收入先进入估算投影，使学生转就业或新工资在同一事务生效；收入减少本身不得自动向下改写既有支出。
- 无 Accepted 生活安排变化时，系统不得自动向下改写既有持续支出。

## 4. 分类拆分与防双算

目标总额记为 `T`，当前已接受的分类持续支出合计记为 `C`，未分类余额记为 `U`。

- 初次建立：`U = max(0, T - C)`。
- 新的 Accepted 分类责任增加 `deltaC` 时，同一生效月原子执行：`U' = max(0, U - deltaC)`。
- 当 `deltaC > U` 时关闭未分类账户，超出部分真实提高总支出。
- 分类责任结束或降低时，不在同一节点自动放大 `U`；只有新的上下文复核结果可以上调估算。
- 仍有 active legacy aggregate 时，不建立新未分类账户，避免覆盖关系不明导致双重计提。

## 5. 展示与审计

财务摘要必须同时暴露：

- `annualizedActiveExpenseWan`：账本实际计提总额；
- `unclassifiedAnnualizedExpenseWan`：未分类估算额；
- `confirmedTypedAnnualizedExpenseWan`：可作为分类事实陈述的金额；
- `reportEligibleAnnualizedExpenseWan`：终局报告允许引用的金额。

发布审计增加未分类支出节点数、人月数、金额人月占比，以及已确认分类支出金额人月占比。`0/0` 必须显示 `not_covered`，不得显示 100%。年化支出众数和储蓄率用于发现异常，不作为自动扣款或发布成功条件。

## 6. 验收

- 有工资、仅有 0.35 万/月基础线的成年人，实际年化支出不再停留于 4.2 万。
- 静默节点沿用既有总额，不重复建账、不回落到最低线。
- Accepted 住房/医疗/家庭支出出现时，未分类余额同月减少，核心支出不双算。
- 被拒绝的节点对时间、收入、现金和全部支出账户零变化。
- 学生家庭同住、学生非家庭住宿、成年人就业、退休复核分别有定向测试。
- 企业场所、公司运营和第三方付款不得进入个人未分类或住房账户。
- 开发阶段只跑受影响静态门禁和一条短真实路线；最终代码、配置和提示词冻结为干净候选后，只跑一次全新 2/2/1 作为正式发布证据。
